## 0.22.1 (2026-11-14)

Expanded Java and Scala project analysis, with explicit opt-in JVM tools and clearer coverage failures. Scala remains in beta.

Validation: 2,621 unit/regression tests and nine opt-in real-tool checks pass; self-scan scores 100/100.

### Added

- SpotBugs and find-sec-bugs analysis of compiled Java and Scala classes, with portable argument files for large classpaths and paths containing spaces.
- OWASP Dependency-Check integration for resolved Java and Scala dependencies, including transitive JARs, cached advisory data, and explicit NVD feed updates.
- Read-only SpotBugs SARIF and Dependency-Check JSON imports, source mapping, deduplication, and incremental scan scope.
- `aislop-tools --jvm-security` provisions pinned, checksum-verified tools. Live scans require `--jvm-security` as well as project configuration.
- A caller-managed scalafmt JVM classpath for environments that do not use a native launcher.
- Real-tool integration coverage for Java 8/17/21 bytecode, Scala 2/3, scalafmt roundtrips, and vulnerable dependency JARs.

### Fixed

- Invalid JVM configuration, missing artifacts, malformed reports, missing classes, and analyzer failures produce explicit errors instead of clean results.
- Bundled assets resolve correctly for the scoped GitHub Packages installation.
- Recognize Homebrew formula and cask download URLs as package metadata while retaining application URL and provider ID checks.

## 0.22.0 - 2026-11-14

Optional Java tool installation and more reliable Java and Scala analysis. Scala remains in beta.

### Added

- **Java tool installation.** `aislop-tools --java` downloads pinned, checksum-verified google-java-format, PMD, and Checkstyle distributions. Requires JDK 21+ and preserves existing executable system tools.
- **Scala 3 catch checks.** Indentation-based catch clauses respect dedents and nested match expressions.

### Fixed

- **Scala formatting results.** Correctly handle scalafmt's formatting-difference exit code and file URLs, including paths with spaces.
- **Java analyzer failures.** Report tool and configuration errors clearly instead of returning zero findings. Source arguments are batched as absolute paths.
- **Project check execution.** Keep explicitly enabled project shell checks separate from analyzer argument execution.

## 0.21.0 - 2026-11-13

A minor release with per-run rule ignores, scan-scope explanations, opt-in post-fix project checks, and initial Scala support in beta.

### Added

- **Scala language support, beta (#539).** Scala sources and sbt/Mill builds are detected, with opt-in scalafmt, import/exception/console patterns, SQL/process/deserialization checks, and generic file-size and comment checks. Integrates j5ik2o's implementation with follow-up accuracy fixes. Coverage and accuracy are still being refined; Scala 3 indentation-based syntax and real-world scalafmt integration remain ongoing work.

- **CLI rule ignores (#533).** `aislop scan --ignore <rule>` disables repeatable or comma-separated rule IDs for one invocation, including when file overrides enable them.

- **Scope explanation (#319, #481).** `aislop scan --explain-scope` reports effective file selection as text or versioned JSON without running engines. Verbose output adds relative examples; excluded files and skipped directories are counted separately.

- **Post-fix project checks (#322, #480).** Repeatable `--check` commands verify fixes and roll back fixer-owned changes on failure. Configured commands require explicit `--run-checks`; snapshots respect scope and exclusions, and partial restore failures are reported without deleting current files.

### Fixed

- **Rollback coverage and Scala import advice.** Full-project checks also restore fixer changes outside scan include patterns. Duplicate Scala imports are checked within consecutive import groups, and unused-import advice is limited to Java imports because Scala imports can supply implicits without textual references.

- **Timeout rollback ordering.** Timed-out project checks finish terminating their process tree before rollback starts, preventing late writes and Windows working-directory locks.

- **Rust literal masking (#412).** Braces in strings, character literals, raw strings, and nested comments no longer inflate function lengths. Lifetimes and labels remain visible as code.

- **Scala package discovery and interpolation.** JVM package paths under Scala source roots remain in scope, including packages named `example` or `samples`. Executable expressions inside interpolated strings remain visible to import and security checks while literal text stays masked.

### Changed

- **Dependency updates (#515-#519).** Update React to 19.3.1, oxlint to 1.92.0, MCP SDK to 1.32.2, tsdown to 0.23.7, and smol-toml to 1.9.1.

## 0.20.1 - 2026-11-11

A patch release that fixes Python diagnostic false positives and reduces CPU work when security checks produce many findings.

### Fixed

- **Python string boundaries.** Triple-quoted examples, escaped quotes and comments no longer hide real print statements or trigger bare-handler and swallowed-exception findings inside strings. Real statements remain reported.
- **Security diagnostic line lookup.** Secret and risky-code checks advance a newline cursor per pattern instead of repeatedly splitting source prefixes for each finding. Finding contents and line positions remain unchanged, with linear newline-counting work on large inputs.

## 0.20.0 - 2026-11-01

A minor release. `aislop scan --share` prints a public report link and README badge for GitHub repos, and the scan summary points to it instead of the team invitation.

### Added

- **`aislop scan --share`.** For a project with a GitHub `origin` remote, prints the public report link `https://scanaislop.com/<owner>/<repo>` and the README badge markdown. The report works for public repos only. The link is built from the local remote: nothing is uploaded and no network call is made. `ssh://git@github.com/...` remotes are now recognised as well.

### Changed

- **Scan summary hint.** Interactive scans end with `Share this report: aislop scan --share`. The hint is left out of JSON and SARIF output, piped output, CI runs, `aislop ci`, and runs that already pass `--share`.

### Removed

- **Team invitation after the third scan.** The "Using aislop with a team?" line and the local counter behind it are gone. Existing counter files are ignored.

## 0.19.1 - 2026-10-28

A patch release. Info notices such as `knip/skipped` no longer fail a baselined `aislop ci` run.

### Fixed

- **Info notices no longer fail a baselined `ci` run.** With a CI baseline, 0.19.0 counted the info notice `knip/skipped` as a new finding, so projects with a baseline and no Knip setup failed `aislop ci`. Info notices are still reported but no longer count as new findings.

## 0.19.0 - 2026-10-28

Java support, a `quality.knip` setting, and fixes for false positives and missed findings across several rules.

### Added

- **Java support.** Java projects get formatting (google-java-format), linting (PMD, plus Checkstyle when the project has a `checkstyle.xml`), security checks for SQL and process commands built by concatenation and for unsafe deserialization, and AI-slop rules including the new `ai-slop/java-broad-throws`. `aislop doctor` shows the Java tools and how to install them.
- **`quality.knip`.** `auto` (default) runs Knip for projects that declare or configure it, `always` runs the bundled Knip on every JavaScript or TypeScript project, and `off` never runs it. `always` runs code from the scanned repository, because Knip loads its config files.
- **`knip/skipped` notice.** An info finding reports when Knip is not set up, times out, or fails, instead of the check disappearing silently.

### Changed

- A knip config file or a `"knip"` key in `package.json` now counts as using Knip. aislop always runs its own bundled Knip.
- Links to scanaislop.com carry utm parameters. The visible link text is unchanged.

### Fixed

- `.aislop/config.yaml` and `rules.yaml` are now read. When both spellings exist, `.yml` wins. Run `aislop hook install` again so the Claude Code `FileChanged` hook watches both.
- `ai-slop/unused-css` and `security/hardcoded-secret` check stylesheets and config files (`.yaml`, `.yml`, `.json`, `.toml`) on real scans again. Upgrading can surface dead CSS that was always there.
- Fewer `ai-slop/hardcoded-url` false positives on vendor hosts, `.dev`/`.app` domains, social profiles, and legal pages.
- `ai-slop/unsafe-type-assertion` ignores comments, and `eslint/no-undef` respects `/* global */` directives.
- `knip/files` findings are reported again with Knip 6.
- Agent hooks write lock, baseline, and session files at the project root.
- `security/vulnerable-dependency` no longer suggests a downgrade as an upgrade.
- No `EPIPE` crash when the output reader closes early (for example, piping into `head`).
- Patched dependency advisories in `vite`, `zod`, `vitest`, `body-parser`, `fast-uri`, `ip-address`, and `qs`.

## 0.18.1 - 2026-10-06

Patch release. Pinning the GitHub Action now pins the CLI too, so Dependabot keeps both current.

### Changed

- **Action ref selects the CLI version.** `uses: scanaislop/aislop@v0.18.1` runs `aislop@0.18.1`, a commit SHA runs that commit's version, and `@v1` still runs the latest release.

### Fixed

- `aislop agent` shows the provider's own error output when a session fails, not just an exit code.
- Patched dependency advisories in `proxy-addr`, `source-map-js`, and `smol-toml`.

## 0.18.0 - 2026-10-03

Baseline release. Adopt aislop on an existing codebase and gate CI on new findings only, plus fixes for false positives reported by users.

### Added

- **Baseline mode.** `aislop baseline write` records today's findings. With `ci.baseline` set, CI fails only on new findings. Findings match on line content, not line numbers, so unrelated edits do not resurface them. Opt-in.
- **`imports.provided`.** Lists modules your runtime supplies so Python import checks do not flag them.

### Changed

- Python import checks read every `requirements*.txt` file, `-r` includes, and PEP 723 script metadata.
- Biome and ruff follow your project's own config, and aislop uses the ruff pinned in your virtualenv. A missing tool is reported instead of silently skipped.

### Fixed

- Fewer false positives on UI copy under password-like keys and on Go `v, _ := f()`.
- A bare `aislop-ignore` directive now works.

## 0.17.0 - 2026-10-02

Per-file overrides, a fourth agent provider, and clearer failure reporting. One scan can now hold controllers, services, and generated code to different standards.

### Added

- **Ordered overrides.** `overrides` in `.aislop/config.yml` apply glob-matched quality limits and rule severities; later entries win. Opt-in.
- **pi provider.** `aislop agent` can run repair sessions on pi, alongside Codex, Claude Code, and OpenCode.

### Changed

- A scan with no aislop hook installed suggests installing one, and suggested commands work when run through `npx`.

### Fixed

- `aislop fix` keeps exports that are still used in their own file instead of deleting them.
- `aislop badge` detects repositories with dots in their names.

## 0.16.1 - 2026-09-09

Maintenance release. Four rule fixes, three from outside contributors, that stop findings firing where they should not and catch handlers that were slipping through. Scores can move in either direction.

### Fixed

- Python `logger.exception` is no longer treated as swallowing an error, since it attaches the traceback.
- URLs inside Python docstrings are read as documentation rather than hard-coded endpoints.
- `target/`-style build directories are pruned, so Rust projects are not scored on generated code.
- Multi-line Python `except` bodies are read as whole statements, so handlers wrapped across lines are no longer skipped.

## 0.16.0 - 2026-08-30

Scoping release. `fix` and `scan` can be pointed at what changed rather than the whole tree, and `fix` can show what it would do before it writes anything.

### Added

- **`aislop fix --dry-run`.** Prints the planned fix steps, including skipped steps and why, without writing files. Cannot be combined with an agent handoff or `--prompt`.
- **`aislop fix --changes`, `--staged`, and `--base`.** Restricts fixes to changed or staged files, matching the flags `scan` already accepted.
- **Changed-line context on findings.** Diagnostics are classified as changed-line or existing-file context in terminal, JSON, and SARIF output.

### Fixed

- Dependency, audit, and Expo alignment fixes stay inside the selected scope.
- Scoped `fix` no longer rewrites test files that a plain `fix` leaves alone.
- Scoped `fix` and `scan` agree on the score for the same selection.
- `fix` respects `CI=true` as well as `CI=1`, so spinner sequences do not leak into GitHub Actions logs.
- C# and C/C++ formatters appear in the dry-run plan.

## 0.15.0 - 2026-08-26

Calibration release. Scores now describe how code is written rather than how much of it there is. **Every score moves in this release**, most of them upward. Re-baseline CI gates and badges after upgrading.

### Changed

- **Score reflects finding density, not project size.** Deductions are divided by file count before the scoring curve, so a large project and a small one with the same habits land on the same number.
- **Rule caps scale with project size.**
- **Default `scoring.smoothing` lowered from 20 to 5.**

### Fixed

- **`ai-slop/trivial-comment`** no longer flags ordinary terse comments. It now requires a file saturated with them (at least one per 50 non-blank lines).
- **`security/vulnerable-dependency`** reports `devDependencies` as `dev-only` at `info` severity instead of treating them as shipped risk.
- **`ai-slop/python-mutable-default`** no longer flags call-wrapped keyword arguments such as FastAPI `Body(default={})`.
- **`doctor`** derives languages from the configured scan scope rather than from manifests alone.

## 0.12.0 - 2026-06-10

Local agent repair sessions get a full terminal-native workflow, CLI output is tighter across the command surface, and scoring now separates cosmetic cleanup from higher-impact findings.

### Added

- **`aislop agent` terminal UI.** Foreground agent sessions now render a live terminal UI with steps, activity, edited files, score and target, passes, token usage, and in-terminal decisions. Non-TTY and CI runs keep plain streamed output.
- **Agent workflow commands.** Added provider status, connect, default-provider, background sessions, session list/show/watch/apply/stop commands, monitor mode, safe local apply, and optional commit/PR publishing from a reviewed agent diff.
- **Command suggestions.** Mistyped commands now get nearest-command guidance instead of falling through to confusing directory-scan errors.
- **Rule impact metadata.** JSON output, finding assessment, and `aislop rules` now expose per-rule score-impact tiers so integrations can distinguish mechanical cleanup from stronger quality and security signals.

### Changed

- **Scoring calibration.** The default `ai-slop` weight is softer and rule scoring now uses impact multipliers and caps, preserving real findings while reducing score swings from low-impact style signals.
- **Terminal rendering.** Scan summaries, badges, rules, doctor, hook, update, trend, provider, and agent outputs use aligned display sections and clearer action guidance.
- **Source filtering and lint context.** Generated, vendor, package-manager, and docs-like artifacts are excluded more consistently. ESLint globals and ignores are respected, PHP-served browser JavaScript gets softer `no-undef` handling, and `ruff` follows the same scoped file selection as `aislop`.

### Fixed

- **Agent telemetry coverage.** `aislop agent` and its provider, plan, monitor, session, apply, watch, and stop subcommands now emit the same lifecycle telemetry as the rest of the CLI, without sending paths, branch names, session ids, prompts, raw findings, or transcripts.
- **Agent subdirectory scope.** `aislop agent`, `agent plan`, and monitor repair now honor a requested subdirectory in monorepos instead of scanning or fixing the repository root.
- **Agent worktree diffs.** Agent apply/publish flows now include staged and untracked files, so provider edits are not skipped when the isolated worktree contains pending changes outside the unstaged diff.
- **Monitor debounce behavior.** Monitor mode now waits for stable dirty snapshots without resetting the debounce timer on every poll, while preserving immediate reactions for `--debounce 0`.
- **Background stop handling.** Monitor stop now signals the monitor process group on non-Windows platforms, matching background session stop behavior so active provider subprocesses are not left editing.
- **Installer and CI stability.** Tool downloads retry transient GitHub/network failures, the terminal UI dependency stays compatible with the documented Node `>=20` floor, and long CLI help-surface tests have explicit CI-safe timeouts.
- **Python and Go calibration.** Python manifest/import resolution handles nested manifests and additional stdlib/package aliases, and Go panic heuristics exempt test-support code.

## 0.11.0 - 2026-06-06

PR-scoped quality gates and set-and-forget CI. `scan` and `ci` can gate a pull request on only the files it changed with `--changes --base <ref>`, and an explicit base ref that cannot be resolved fails the run instead of silently passing an empty scan. A moving `v1` Action tag plus `version: latest` mean workflows do not need a version bump, and CI examples standardize on Node 24.

### Added

- **`--base <ref>` and `ci --changes`.** Both `scan` and `ci` accept `--changes --base <ref>` to diff against a branch instead of `HEAD`, so a pull request can be gated on only the files it touches even when those files are already committed.
- **`forceFixable` flag.** `scan --json` diagnostics carry an explicit `forceFixable` boolean for findings that only `aislop fix -f` resolves.

### Changed

- **Set-and-forget CI.** A moving `v1` Action tag tracks the latest release, so workflows can pin `uses: scanaislop/aislop@v1` and keep `version: latest`.
- **Node standardized on 24.** CI examples use Node 24. The supported runtime floor remains Node `>=20`.

## 0.10.2 - 2026-06-02

A patch release focused on safer release and CI plumbing, sharper scan consistency, and rule catalog alignment.

### Added

- **Inline suppression.** Suppress known intentional findings with `aislop-ignore-next-line`, `aislop-ignore-line`, or `aislop-ignore-file`, optionally scoped to specific rule IDs and a reason.
- **`.aislopignore`.** Keep whole paths out of every scan with a root-level ignore file.
- **`aislop fix --safe`.** Restrict auto-fix to reversible fixes such as unused imports, import merging, narrative-comment removal, and formatting.

### Fixed

- **Exact-version Action pins.** Exact npm pins run from an isolated temp directory so npm cannot resolve checked-out local package metadata instead of the published package.
- **Rule catalog consistency.** `aislop rules`, rule labels, and docs cover implemented rule IDs consistently.
